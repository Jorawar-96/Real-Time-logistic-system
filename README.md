Uber Clone - MERN Full Stack
A comprehensive real-time ride-sharing application built using the MERN stack. This project features a dual-interface system for Users and Captains, utilizing WebSockets for live interactions and a secure OTP-based handshake to start journeys.

Project Overview
This application automates the entire taxi-hailing process. It handles user authentication, real-time ride broadcasting to nearby drivers (Captains), secure ride validation via OTP, and live tracking from pickup to drop-off.

Core Features
1. User and Captain Authentication
JWT Token Integration: Secure login and registration for both Users and Captains using JSON Web Tokens.

Protected Routes: Middleware-backed API endpoints that ensure only authorized users can request rides or accept them.

Password Hashing: Industry-standard encryption for storing user credentials securely in MongoDB.

2. Real-Time Ride Management
Ride Request: Users can raise a ride request which is instantly broadcasted to available Captains in the vicinity.

Live Acceptance: Captains receive a real-time notification via Socket.io and can accept the ride with a single click.

Status Updates: The User is notified immediately when a Captain accepts their request.

3. Secure OTP Handshake
Ride Verification: Once the Captain reaches the pickup location, the User provides a unique 4-digit OTP generated by the system.

Ride Start: The ride status updates to "Ongoing" only after the Captain enters the correct OTP into their interface.

Safety First: This ensures that the Captain picks up the correct passenger every time.

4. Journey Completion
Live Tracking: Real-time location updates throughout the duration of the trip.

Ride End: Upon reaching the destination, the Captain terminates the ride, updating the status to "Completed" and finalizing the transaction.

Technical Architecture
Backend Structure
controllers: Contains the logic for handling requests, including user profiles and ride lifecycles.

services: Abstraction layer for complex tasks like calculating fares and validating OTPs.

models: Schema definitions for Users, Captains, and Ride data.

socket.js: The engine driving real-time communication between the client and server.

db: Configuration for the MongoDB connection.

Frontend Structure
pages: Dedicated views for Login, Signup, Home, and the Live Ride tracking interface.

context: Centralized state management for handling authentication tokens and socket connections across the app.

components: Modular UI elements like the search bar, captain details card, and OTP input modal.

Setup and Installation
Backend Setup
Navigate to the backend directory and install dependencies using npm install.

Configure your environment variables in a .env file, including your MongoDB URI, JWT Secret, and Port.

Start the server using node server.js or npm start.

Frontend Setup
Navigate to the frontend directory and install dependencies using npm install.

Ensure the backend URL is correctly pointed in your configuration.

Launch the development server using npm run dev.

Deployment Note
Ensure that both the frontend and backend environment variables are correctly set up for production, specifically the Socket.io CORS settings to allow communication between your deployed domains.
